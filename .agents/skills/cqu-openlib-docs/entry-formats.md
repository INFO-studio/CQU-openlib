# 资源条目格式

站点的资源条目是**一行一条**的列表项，字段用 ` - `（半角空格 + 连字符 + 半角空格）分隔，每个字段是 `:l-图标:` 紧跟一段反引号包裹的值。全库 350+ 条书目零例外地遵守这个形状，照抄即可。

## 教材 / 书目

```markdown
    * [教材](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-book-open:`书名` - :l-user:`第一作者` - :l-printer:`出版社`␠␠
```

`␠␠` 表示**行尾两个空格**，必须有。

### 字段

| 顺序 | 图标 | 内容 | 必填 |
| --- | --- | --- | --- |
| 1 | `:l-book-open:` | 书名 | 是 |
| 2 | `:l-user:` | 第一作者 | 是 |
| 3 | `:l-printer:` | 出版方（书上印的那个单位） | 是 |
| 4 | `:l-gallery-vertical-end:` | 版次 | 可选 |
| 5 | `:l-scan-barcode:` | ISBN13 | 可选 |

顺序不可调换。可选字段追加在必填三段之后，没有就整段省略（连 ` - ` 一起省）。

带全部字段的样子：

```markdown
    * [教材](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-book-open:`泌尿系统与疾病` - :l-user:`第一作者` - :l-printer:`人民卫生出版社` - :l-gallery-vertical-end:`第2版` - :l-scan-barcode:`9787117325745`␠␠
```

### 逐字段规则

**书名**：不加书名号《》。分册标记写进书名，用全角括号：`高等数学（上）`。版次**不要**写进书名，用第 4 个字段。`（C语言版）`、`（Verilog版）`、`（MySQL版）` 这类是书名本体，保留在书名里。

**作者**：**只写第一作者**。全库 350+ 条没有一条出现「、」「,」「等」。编写组作者带书名号：`《西方经济学》编写组`、`2023版编写组`。外文作者照书上印的原文写，不译成中文、不缩写。

**出版方**：写全称。多家用 `&` 连接：`高等教育出版社&人民出版社`。校内讲义就写院系：`重庆大学自动化学院`。

**版次**：**只有用户明确说明「第几版」时才录入。** 不得根据 ISBN、出版时间、网页书目或 PDF 内容自行查询、推断或补充版次。录入时一律写成 `第N版`，N 用阿拉伯数字；用户给出中文数字（「第七版」「第三版」）时转成 `第7版`、`第3版`。

**ISBN**：只写 13 位数字，不加 `ISBN` 前缀（条码图标已经表意）。

### 链接文本

`[教材]` 是默认。分册用 `[教材上册]`、`[教材中册]`、`[教材下册]`。同书不同版本用 `[教材（原版）]`、`[教材（重排）]`。其它已在用的：`[实验教材]`、`[习题集]`、`[教辅]`、`[参考教材]`。

### 附属文件

习题解答、习题集这类挂在教材下面**作为子列表**，只给链接，不重复三段元信息：

```markdown
    * [教材上册](https://api.cqu-openlib.cn/file?key=AAA) - :l-book-open:`高等数学（上）` - :l-user:`第一作者` - :l-printer:`高等教育出版社`␠␠
        * [高等数学上册习题解答](https://api.cqu-openlib.cn/file?key=BBB)
```

### 行尾备注

写在整行末尾的全角括号里，不要塞进反引号：

```markdown
- [教辅](https://api.cqu-openlib.cn/file?key=CCC) - :l-book-open:`概率论与数理统计《原神》版教学辅导用书` - :l-user:`展未央` - :l-printer:`须弥教会院出版社`（内容确实很牛）
```

## 试卷

```markdown
        * [试卷+答案](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-calendar:`2024秋` - :l-tag:`A卷`␠␠
```

- 链接文本三选一：`试卷+答案`（175 例）、`试卷`（84 例，无答案时）、`答案`（14 例，只有答案时）
- `:l-calendar:` 写学期：`2024秋`、`2021春`，年份 + 春/秋，中间无空格
- `:l-tag:` 写卷别：`A卷`、`B卷`
- 只有试卷没答案时，行尾补 `（暂无答案）`
- 同一门课多个学院出卷时，在学期和卷别之间插 `:l-building-2:`学院名``：

```markdown
        * [试卷+答案](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-calendar:`2025秋` - :l-building-2:`数统学院` - :l-tag:`A卷`␠␠
```

## 其它字段

`:l-file-text:` 标注文档类资源的名字：

```markdown
    * [文档](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-file-text:`学堂在线答案`␠␠
```

`:l-quote:` 只用在**不是书名**的标题位（占位「暂无教材」、试卷范围描述、贡献者自己写的笔记标题）。是出版物就用 `:l-book-open:`。

## 贡献者署名

贡献者名单、更新日志和资源条目的署名相互独立：贡献者可以进入名单、在更新日志中署名，但不一定写到资源条目末尾。

**教材默认不在资源条目末尾署名。** 普通上传、代为收集或转交公开可获取的教材电子版，只把提供者加入贡献者名单，并可在更新日志中署名。只有以下两项同时成立时，才在教材条目末尾署名：

1. 该教材电子版此前无法在公开网络找到。
2. 信息提供者本人完成了教材扫描。

符合条件的教材条目：

```markdown
    * [教材](https://api.cqu-openlib.cn/file?key=FILEKEY) - :l-book-open:`书名` - :l-user:`第一作者` - :l-printer:`出版社` @ [贡献者名](../contributor/贡献者名.md)␠␠
```

其他资源需要标明直接贡献者时，也沿用相同的行尾格式：

```markdown
    * [公式汇总](https://api.cqu-openlib.cn/file?key=FILEKEY) @ [贡献者名](../contributor/贡献者名.md)␠␠
```

`@` 后面跟指向 `contributor/` 页的相对链接。**`@` 后面必须有一个空格**，不要写成 `@[名字]`。贡献者没有个人页时直接写名字，空格照留：`@ 名字`。

### 贡献者名单顺序

`public/doc/contributor/index.md` 的贡献者名单以现有写法隐式分段：有个人简介页的链接条目连续放在上方，没有个人简介页的纯文本条目连续放在下方；不要为这两段另加小标题。

- 两段内部都按首次收录时间升序排列；新贡献者默认追加到对应段末尾，不按姓名、贡献次数或活跃程度重新排序。
- 改名不改变原位置。已有贡献者后来补建个人简介页时，将其从下段移入上段，并按其首次收录时间放置；无法可靠确认历史顺序时，追加到上段末尾。
- 只有用户明确指定顺序，或有证据表明历史顺序错误时，才例外调整。
- “有个人简介”以实际存在且有内容的 `public/doc/contributor/<名字>.md` 为准；只有名单链接、空文件或占位页不算。

## 分组小节

资源多的时候用裸文本列表项分组，不加链接：

```markdown
    * 期末试卷
        * [试卷+答案](...) - :l-calendar:`2023秋` - :l-tag:`A卷`␠␠
        * [试卷](...) - :l-calendar:`2022秋` - :l-tag:`B卷`（暂无答案）␠␠
```

已在用的分组名：`期末试卷`、`期中试卷`、`课件`、`学长共享资源`、`实验报告参考`、`代码参考`、`真题`。

## 课程页骨架

```markdown
---
updated: 2026-07-31
---

## 资源  
=== ":l-book:`课程号`"  
    * [教材](...) - :l-book-open:`书名` - :l-user:`作者` - :l-printer:`出版社`  
```

- 二级标题只用这三个：`## 攻略`、`## 资源`、`## 课外资源`，顺序也是这个。标题行尾同样带两个空格。
- `=== ":l-book:`课程号`"` 是内容 tab，一门课有多个课程号就写多个 tab。tab 内的内容**必须缩进 4 个空格**。
- 同一页面有多个课程代码 tab 时，按课程代码的**字母前缀升序、数字部分升序**排列。例如 `EE30011` 必须排在 `OE31600` 前；这条规则不适用于非课程代码 tab。
- 课程号查 `metadata/course-codes.json`，一条命令见 [site-structure.md](site-structure.md)。别自己编。

### 占位页

无实际内容的课程页只保留 frontmatter：

```yaml
---
placeholder: course
---
```

已有 `updated` 等元数据时保留，并追加 `placeholder: course`。页面展示内容统一来自 `app/utils/placeholderMap.ts`，不会进入全文搜索索引。

往占位页添加真实资源时，整体替换成上面的课程页骨架，并删除 `placeholder`。不要在占位标记下面追加正文。

### 已知教材但没拿到文件

教材已经登记在 `sundry/待办事项/textbook.md`、但文件还没收到时，课程页继续保持纯 `placeholder: course`，不要复制书名、作者、出版社、ISBN 或待办序号。待办页是这类信息的唯一数据源。

页面已有其它资源、缺的只是某本教材或新版次时，也只在待办页登记，不向课程正文追加“未能收集到电子版”的说明。拿到文件后再按正常资源条目写入课程页并兑现待办。

不要用空链接占位（`[教材]()` 配 `:l-quote:` 写「暂无教材」）。

### 待办序号

待办条目的序号形如 `legacy#134`，是旧的微软问卷编号，**这批号不会再新增**。

新条目从站内表单进来，序号是 8 位 id，写成 `#abcdefgh`——即提交 id 的末 8 位，QQ 通知里 `ID：xxxxxxxx` 那串（`CQU-openlib-api` 的 `src/lib/notifySubmission.ts`）。

引用时连 `legacy` 一起写，跟在链接后面用行内代码，不要塞进链接文字里：

```markdown
详见[教材收集](../sundry/待办事项/textbook.md) `legacy#138`
完成 [待办事项-教材需求](../../../待办事项/textbook.md) `legacy#134`
```

**不要写成锚点。** 全站只有标题带 id（`app/utils/headingText.ts` 的 `slugify`），列表项没有 id，`textbook.md#legacy138` 跳不过去。

待办条目本身不写贡献者署名，登记与兑现都要写日志，见 [updated-and-changelog.md](updated-and-changelog.md)。

## 文件链接

资源文件走 API：`https://api.cqu-openlib.cn/file?key=FILEKEY`，filekey 由维护者上传后给出，不要自己构造或猜测。

文档之间用相对路径带 `.md` 后缀（`../contributor/贡献者名.md`），站内工具路由用绝对路径无后缀（`/form/textbook`）。锚点规则和表单 slug 清单见 [site-structure.md](site-structure.md)。
