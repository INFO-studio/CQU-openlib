# `updated` 与更新日志

这两件事共用同一个判断：**读者在页面上看到的信息本身变了吗？** 变了才动，没变一律不动。

## 判定表

先查这张表，再动手。两列是独立的，经常一个动一个不动。

| 你做的事 | 改页面 `updated` | 写更新日志 |
| --- | --- | --- |
| 新增 / 更新 / 下线资源链接、教材、试卷 | 是 | 是 |
| 改正文表述、结论、数据 | 是 | 是 |
| 新建一个有内容的页面 | 是 | 是 |
| 修渲染 bug（某语法不生效、内容显示错误） | 否 | 是 |
| 批量统一格式（图标换名、补行尾空格、缩进） | 否 | 否 |
| 错别字、标点 | 否 | 否 |
| 为配合解析器改动做的等价改写 | 否 | 否 |
| 重构、依赖升级、构建 / CI、测试、性能优化 | 否 | 否 |

「修渲染 bug 不动 `updated`」不是笔误：页面内容一个字没改，改的是解析器，所以日期不动；但读者原先读到的是错的，现在对了，所以要告诉读者。

批量格式统一那一行最容易做错。把 300 多个页面的 `updated` 一起改成今天，等于把「编辑于」这个信号废掉——读者再也看不出哪一页真的更新了。宁可不动。

## frontmatter

```yaml
---
updated: 2026-07-31
---
```

- 已有 frontmatter：把 `updated` 改成**当天**日期。
- 没有 frontmatter：在文件最开头补上整块，后面空一行再写正文。
- 日期必须是 `YYYY-MM-DD` 字符串，不要写时间戳或别的格式。
- 解析器只认 `updated` 和 `description` 两个键（`description` 是可选的短描述，进 `<meta>`）。写别的键等于写注释。实现见 `app/utils/docFrontmatter.ts`。

### 不要加 `updated` 的目录

- `public/doc/index.md`（首页不展示「编辑于」）
- `public/doc/contributor/**`（贡献者个人页）
- `public/doc/sundry/更新日志/**`（日志本身用路径和标题表达日期）

用户明确说不要动日期时，一律跳过。拿不准时**先问**，不要默认加。

## 更新日志

日志是写给读者的，不是 commit log。只记录站点「收录了什么内容」和「内容怎么呈现给读者」的变化。

### 绝对不能出现在日志里

- 管理页和站内工具路由（`app/routes/admin.tsx`、提交审核、表单后台）
- `public/doc/42/**` 的任何改动（该目录不进侧边栏也不进搜索索引）

### 写一次日志要同步改三处

漏掉任何一处，站点上就会对不上。

**第一处** `public/doc/sundry/更新日志/YYYY/YYYY-MM/YYYY-MM-DD.md`

当天的日志文件，不存在就按这个路径新建。一条改动一行，用相对链接指向被改的页面，正文不写 frontmatter：

```markdown
- 新增 [泌尿系统与疾病](../../../../course/泌尿系统与疾病.md) 页 `res: 教材-泌尿系统与疾病-第一作者-人民卫生出版社-第2版`
- 修复正文中形如 `8:00-8:30` 的时间被误认作图标、显示为灰色的问题，见 [新生指南](../../../../academic/入学必看/新生指南.md) 晨曦计划打卡时间
```

资源类改动用 `res:` 简写概括，短横线分隔、**不留空格**，和条目行的字段顺序一致：

```
res: 教材-书名-第一作者-出版社
res: 教材上册-自动控制原理-宋永端-机械工业出版社
res: 教材习题解答-离散数学-左孝凌-上海科学技术文献出版社
res: 期中试卷-MATH10822-2023秋-A-试卷+答案
```

资源是来兑现某条待办的，再补一行 `完成`，序号写法见 [entry-formats.md](entry-formats.md) 的「待办序号」：

```markdown
- 完成 [待办事项-教材需求](../../../待办事项/textbook.md) `legacy#134`
```

同时把 `sundry/待办事项/textbook.md` 里那条**删掉**（不是划掉、不是标注已完成），并把待办页的 `updated` 改成当天。

**第二处** `public/doc/sundry/更新日志/index.md`

要改两个地方：

1. 顶部「最新更新日志：」的链接改成当天。
2. 在对应「年 / 季度 / 月」的 tab 下补一行条目。新建季度或月份 tab 时注意既有顺序：**年升序、季度升序、季度内月份降序、月内日期升序**。

**第三处** `public/doc/index.md`

首页「公告」里 `[更新日志](…) / [YYYY-MM-DD](…)` 那条的日期链接改成当天。只改链接，首页不要加 `updated`。

### 当天已有日志时

三处里往往只剩第一处要改——先确认顶部链接和首页公告是不是已经指向今天，是就别重复改。追加条目到当天文件末尾即可。
